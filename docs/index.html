System One FC · d3:2b on Ollama

What the manager sees,
and what it answers

System One FC is a Laravel 13 football game where you manage against a local System One decision model. At every decision point the game sends one JSON request to Ollama and gets back probabilities. The model generates no text, and the game needs no API key or internet connection.

1. SnapshotDecisionContext::toModelState() writes the match from the model's own side.
2. One requestState and every question from config/manager.php go to POST /v1/systemone.
3. Typed answersProbabilities per option. The engine applies the most likely choice.

The state

The state is ten fields, always written from the deciding team's side: us is System One's club, them is yours.

FieldMeaning
minuteMatch minute, including added time
my_team, opponentClub names, so the instructions can say "my_team"
scoreGoals for and against
possession_last_15Percentage of the last 15 minutes with the ball
shots_last_15Shots for and against in the last 15 minutes
fitnessTeam fitness, 0 to 100, which drains every minute and faster when pressing
current_mentality, pressingWhat the team is doing now
subs_leftSubstitutions remaining, out of three

The full request

This is the exact body sent at 70' with the score 1-1. Four questions of three types are answered in one forward pass: choice (pick one option), noul (yes or no) and score (a level on a scale). The option descriptions matter: they are what the model weighs.

Why it so often plays balanced

It was told to. The mentality instructions say "early on or when level, stay balanced". Five of the six fixed decision points (kick-off, 15', 30', half time and 60') come before the late stages where the instructions call for change, and most matches are level or one goal apart at those points.

When the situation changes, so does the answer. One down at 80' puts 0.69 on the attacking options; two up at 88' puts 0.84 on the defensive ones. Before the wording said when each option is used, d3:2b anchored on balanced even when losing late.

Balanced is also usually right. In a benchmark over ten shuffled fixtures, the model took exactly as many points as a hand-written rule-based manager in the same seat (15 each). To get a bolder manager, change the wording in config/manager.php and check it with make scenarios.

Request and response shapes for every question type are in systemone-api.md. The raw request and response for each example is saved as JSON: kick-off.json · level-at-70.json · losing-late.json · winning-late.json.
